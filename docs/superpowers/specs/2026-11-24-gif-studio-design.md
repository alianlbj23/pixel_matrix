# PixelBoard Studio 設計文件

日期：2026-11-24　狀態：草稿（待使用者確認）

## 1. 這是什麼、為什麼要做

pixel-board 目前換 GIF 或音樂，需要用 Python 轉檔、用 ESP-IDF 重新編譯，再透過 WSL + usbipd 燒錄，只有開發者做得到。

**PixelBoard Studio** 是一個 Windows 程式（**單一個 `.exe` 檔**）。非本科系的使用者拿著跟我們一樣的硬體，操作流程如下：

1. 用 USB 接上板子。
2. 點兩下 `.exe`，出現設定面板。
3. 拖進一個 GIF，可以再加幾首 MP3。
4. 看到 GIF **在他的板子上實際會長怎樣**（1 塊或 2 塊面板）。
5. 調整位置和大小。
6. 按「燒錄」。

整個過程不需要安裝任何東西，也不用打開命令列。

成功的標準：一個從沒碰過 ESP32 的人，5 分鐘內能把自己的 GIF 和音樂換到板子上，而且面板上的畫面跟程式裡的預覽一致。

## 2. 使用者

- 非本科系，不會用命令列，不會安裝開發工具。
- 硬體跟本專案相同：
  - Waveshare ESP32-S3-RGB-Matrix 控制板
  - 1 塊 64x32 HUB75 面板，或 2 塊用排線串接（128x32）
- 電腦是 Windows 10/11 64 位元。

## 3. 目標 / 非目標 / 反目標

### 目標
1. **GIF**：拖進程式後立刻預覽。
2. **預覽要忠實**：
   - 依面板數（1 或 2）顯示，用 LED 點點的外觀，黑色就是不亮。
   - 依每格的實際時間播放，可以暫停、可以逐格看。
   - 預覽畫的就是**即將寫入板子的那份 RGB888 資料**，逐像素一致。
3. **可以調整的項目**：
   - 面板數：1 或 2
   - 版面：
     - 整張縮放，置中
     - 每塊面板一份，例如一對眼睛，左右各一隻
   - X/Y 位置
   - 縮放
   - 亮度
   - 左右面板對調
4. **音樂**（使用者原話：「音樂檔案也要加入」）：
   - 可以拖進 MP3，也可以刪除、調整播放順序。
   - 顯示已用和剩餘容量，總共約 12MB。
   - 可以在程式裡試聽。
   - 燒錄後，板子在背景依順序循環播放，跟現在的行為一樣。
5. **一個「燒錄」按鈕**，程式自動判斷要做哪一種：
   - **首次安裝**：板子上沒有相容韌體。寫入完整韌體、GIF，有音樂的話也寫入音樂。
   - **更新**：板子上已有相容韌體。只寫入有變動的區塊（GIF、音樂），幾秒到幾十秒內完成。
6. **自動找到板子**：用 USB VID:PID `303a:1001` 自動挑出板子的 COM port。插了多塊時讓使用者選。
7. 有明確的進度和錯誤訊息，用白話說明。例如：
   - 「找不到板子，請確認 USB 線是資料線，並接在板子的 Type-C 資料口，不是 POWER 口」
   - 「這個 GIF 超過 64 格」

### 非目標（這一版不做）
- 在程式裡剪輯或轉檔音樂。只接受 MP3，不做裁剪、音量調整或格式轉換。
- 在程式裡畫圖或編輯 GIF 內容。
- macOS、Linux 版本。
- 透過 Wi-Fi 無線更新。
- 讀回板子上現有的 GIF 或音樂清單。
- 自動更新程式本身。

### 反目標（就算功能能動，出現這些也算失敗）
- 使用者必須安裝 Python、驅動程式、WSL，或打開命令列。
- 預覽和面板上的畫面不一致，例如位置、大小、顏色或速度不同。
- 燒錄後板子無法開機，或在使用者沒有要求時洗掉了音樂。
- 燒錄失敗後，板子什麼都不顯示，使用者也不知道怎麼救。

## 4. 限制

- **執行環境**：Windows 10/11 64 位元。
  - 畫面用系統內建的 Edge WebView2 顯示，Win10 新版和 Win11 都已內建。
  - 偵測不到 WebView2 時，要用白話提示怎麼安裝。
- **USB**：板子用 ESP32-S3 內建的 USB Serial/JTAG（`303a:1001`），Windows 不需要另外裝驅動。
- **面板**：
  - 每塊 64x32，最多串 2 塊
  - 亮度目前設 90/255，用來限制電流
- **Flash**：模組有 32MB，目前用前 16MB。
- **現有韌體的行為要保留**：
  - 開機依序全螢幕紅、綠、藍，接著顯示 HELLO 並播開機音效
  - 背景循環播放 MP3
  - GIF 動畫一直循環
- **沿用 `tools/gif2c.py` 的限制**：
  - 最多 64 格
  - 每格 20–10000 ms，沒有設定就用 100 ms
  - 輸入檔最大 10MB
- **沿用韌體對 MP3 的限制**：
  - 取樣率 8–48kHz
  - 單聲道或雙聲道
  - 檔名最長 60 bytes
- **專案規則**（使用者的全域規則）：
  - 新增相依套件要先問，並固定版本
  - 外部輸入（檔案、序列埠）要驗證
  - 硬體 I/O 要設 timeout
  - 錯誤要記錄並回報，不能吞掉
  - 新功能要有正常路徑和錯誤路徑的測試

## 5. 已和使用者確定的做法

- **交付物**：單一個 `.exe`，點兩下就出現設定面板（使用者選擇 exe，不要 html）。
- **流程**：插上板子 → 丟進 GIF → 依面板數預覽 → 調整位置 → 燒錄。
- **音樂**：音樂檔也要能加入。
- **可調整**：位置可以調整。

## 6. Claude 做的技術決定（builder 可以挑戰）

### 6.1 Flash 分割：新增 gif 區，音樂區位置不變

新的分割表：

| 名稱 | 大小 | 位置 | 說明 |
|---|---|---|---|
| nvs | 0x6000 | 0x9000 | 不變 |
| phy_init | 0x1000 | 0xF000 | 不變 |
| factory | 2M | 0x10000 | 從 3M 縮小；目前韌體約 1.03MB，仍有一半空間 |
| gif | 1M | 0x210000 | 新增 |
| audio | 12M | 0x310000 | 位置和大小不變，格式改成 6.3 的 PXA1 |

### 6.2 GIF 資料格式 PXG1，韌體開機時讀取

目前 GIF 是編譯進韌體的，改成開機時從 `gif` 分割區讀取。格式全部用 little-endian：

- **標頭**：
  - magic `"PXG1"`
  - 格式版本
  - 面板寬（64）
  - 高（32）
  - 串接數（1 或 2）
  - 亮度
  - 旗標：bit0 = 左右面板對調
  - 格數
  - 資料長度
  - CRC32
- **格表**：每格的持續時間（ms）。
- **畫面資料**：每格 寬 x 高 x 3 bytes，RGB888，逐列排列。
- **容量**：128x32 一格 12KB，64 格約 768KB。

開機流程：
1. 先讀 `gif` 區，驗證標頭和 CRC。
2. 驗證通過：用標頭裡的串接數、亮度、對調旗標初始化面板。**面板數改由程式決定，不再寫死在 `board_config.h`。**
3. 驗證失敗，或格式版本不認得：用 `board_config.h` 的預設值初始化，並顯示內建的「NO GIF」提示畫面，不讓面板全黑。

### 6.3 音樂資料格式 PXA1，取代 SPIFFS

`audio` 分割區改用簡單的打包格式，全部用 little-endian：

- **標頭**：
  - magic `"PXA1"`
  - 格式版本
  - 檔案數
  - 資料總長
  - CRC32
- **檔案表**：每筆包含：
  - 檔名（UTF-8，最多 60 bytes）
  - 位移
  - 長度
  - 順序就是播放順序
- **資料**：MP3 原始位元組直接接在後面，不做轉換。

韌體端：
- `mp3_player` 改成用 `esp_partition_read` 依檔案表串流讀取，不再掛載 SPIFFS。
- 解碼和播放迴圈沿用現有的。
- 標頭或 CRC 錯誤時，記錄錯誤、不播放，GIF 照常顯示。

燒錄時只寫入「標頭 + 實際資料」的長度，不用每次都寫滿 12MB。

開發者流程：
- `assets/audio/` 改用 Python 打包工具產生 PXA1，取代 `spiffs_create_partition_image`。
- `menu.sh` 的 Build/Flash 行為維持不變。

### 6.4 桌面程式的技術選擇
- **語言是 Python**，直接重用和擴充現有的 `tools/gif2c.py`。
  - GIF 處理、PXG1 和 PXA1 打包都用同一套 Python 程式碼，`menu.sh` 和 exe 共用。
  - 預覽和燒錄用的資料由同一個函式產生，所以一定一致。
- **介面**用 `pywebview`，在 WebView2 視窗裡顯示 HTML/CSS/JS 介面。
  - 預覽的 LED 點點、拖放檔案、試聽 MP3，用網頁技術做比較自然。
  - JS 只負責畫面，影像處理和燒錄都在 Python 端。
- **燒錄**用 Espressif 官方的 `esptool`（Python 版），呼叫它的 Python API，不呼叫外部指令。
  - 連線、寫入、讀取都要設 timeout。
  - 失敗時要把原因轉成白話訊息。
- **打包**用 `PyInstaller` 做成單一 `.exe`。
  - 預先編譯好的 bootloader、分割表和韌體二進位檔一起包進去。
  - 打包要在 Windows 端執行。開發機的 Windows 已有 Python 3.13，可以從 WSL 呼叫。
  - `menu.sh` 加一個選項「Build Studio exe」：先 build 韌體，再複製二進位檔，最後用 Windows 的 Python 打包。
- **新增的相依套件，要經使用者同意，並固定版本**：
  - `pywebview`
  - `esptool`
  - `pyserial`（esptool 的相依套件）
  - `PyInstaller`（只在打包時用）
  - Pillow 已經在用。

### 6.5 怎麼判斷相容韌體

程式讀取板子 0x10000 開始的 app 描述（`esp_app_desc_t`）中的 `project_name` 和 `version`：

| 板子狀態 | 程式的動作 |
|---|---|
| `project_name` 是 `pixel-board`，版本跟 exe 附帶的相同 | 只寫有變動的 gif 區和 audio 區 |
| `project_name` 相同，但版本不同 | 提示「更新韌體」，寫入韌體、gif，有音樂的話也寫 audio |
| 其他情況 | 首次安裝：寫入 bootloader、分割表、韌體和 gif；有加音樂的話也寫 audio |

### 6.6 調整的方式
- 整個內容共用一組 X/Y 平移和縮放。
- 分割模式下，每塊面板套用同樣的平移和縮放，兩隻眼睛會一起移動。
- 每次調整都**從原始 GIF 重新計算**，畫質不會越調越差。
- 每塊面板只畫自己那一份，內容不會跨過接縫。
- **亮度**：
  - 滑桿範圍 10–128，預設 90。上限 128 是為了避免一般電源供電不足。
  - 預覽會套用跟面板函式庫相同的 CIE 亮度校正來模擬。
  - 寫入的 RGB888 位元組一定跟預覽一致；面板實際的亮度只能做近似模擬。

### 6.7 音樂的燒錄規則
- exe 不附帶任何 MP3，避免散布有版權的音樂。
- 使用者在面板上加了音樂並按燒錄，就用面板上的清單**整個取代**板子上的音樂。
- 沒有加任何音樂時，保留板子原本的音樂。
- 燒錄前用白話提示這兩種情況。
- 每個 MP3 加入時就先檢查格式（取樣率、聲道、檔名長度），不合格的當場告知。

### 6.8 連不上板子時的救援
如果自動進入燒錄模式失敗，程式用圖文教使用者：
1. 按住 BOOT 鍵
2. 按一下 RESET
3. 放開 BOOT

然後讓使用者重試。

## 7. 留給 builder 決定

- 介面的視覺設計和元件細節。
- Python 和 JS 的程式結構。
- PXG1 和 PXA1 格式的欄位細節和對齊方式，只要符合 6.2 和 6.3。
- 「NO GIF」提示畫面的樣子。
- exe 的圖示和檔名，例如 `PixelBoard-Studio.exe`。
- 測試怎麼切：
  - Python 的影像處理和打包要有單元測試，包含正常和錯誤情況。
  - 韌體的 PXG1 和 PXA1 解析要有 host 單元測試，包含 CRC 錯誤和版本不符。
  - 燒錄流程至少要在實機上走過「首次安裝」和「更新」各一次。
  - exe 要在一台沒裝 Python 的環境（或乾淨的使用者帳號）實際測試能不能開啟。
